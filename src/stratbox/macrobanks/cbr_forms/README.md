# CBR forms (`stratbox.macrobanks.cbr_forms`)

Домен предназначен для загрузки отчетных форм Банка России, приведения исходных DBF к нормализованному потоку данных и формирования сопоставимых Excel-выгрузок по банкам и отчетным датам.

Поддерживаются формы:

| Код | Форма | Текущий охват |
|---|---|---|
| `101` | `0409101` | существующие аналитические агрегаты по счетам |
| `102` | `0409102` | существующие аналитические агрегаты ОФР |
| `123` | `0409123` | существующие показатели капитала |
| `135` | `0409135` | текущий dataset фактических нормативов |
| `802` | `0409802` | полный основной консолидированный баланс: 86 официальных строк |
| `805` | `0409805` | текущий dataset нормативов банковской группы |

Форма `802` является первой формой, полностью переведенной на целевую модель «физический источник + семантический каталог + canonical long».

## Основной API

```python
from stratbox.macrobanks.cbr_forms import run_all_forms_to_xlsx

out = run_all_forms_to_xlsx(
    date_from="2026-01-01",
    date_to="2026-07-01",
    freq="M",
    anchor="start",
    forms="101,102,123,135,802,805",
    out_dir="outputs/cbr_forms",
)

print(out)
```

Можно запускать только 802:

```python
out = run_all_forms_to_xlsx(
    date_from="2026-04-01",
    date_to="2026-04-01",
    forms="802",
    out_dir="outputs/cbr_forms",
)
```

## Архитектура

Цепочка обработки фиксируется так:

```text
CBR archive
    ↓
forms/formXXX.py
    ↓
physical normalized data
    +
models/formXXX.csv
    ↓
semantic canonical long
    ↓
wide / Excel
```

### Физический источник

Python-модуль формы знает физику источника:

- URL архива;
- нужный DBF;
- физические имена полей;
- кодировку и особенности чтения;
- правила выбора DBF;
- нормализацию физических кодов.

CSV не должен содержать имена физических value-полей вроде `VSEGO`, `C2_3` или `FAKT_ZN`.

### Семантическая модель

Каждая форма имеет отдельный файл:

```text
models/
    form101.csv
    form102.csv
    form123.csv
    form135.csv
    form802.csv
    form805.csv
```

Все файлы используют один header:

```csv
form,order,id,kind,dataset,source_code,parent_code,measure,name,expression,section,unit,params
```

Значение колонок:

| Поле | Назначение |
|---|---|
| `form` | короткий код формы |
| `order` | стабильный порядок вывода |
| `id` | уникальный стабильный `IndicatorId` |
| `kind` | `direct`, `formula` или `passthrough` |
| `dataset` | логический набор данных формы |
| `source_code` | код исходной строки; для `passthrough` — `*` |
| `parent_code` | родительская строка иерархии |
| `measure` | семантический канал значения |
| `name` | отображаемое название |
| `expression` | расчетное выражение только для `formula` |
| `section` | раздел формы |
| `unit` | стандартная единица измерения |
| `params` | редкие дополнительные параметры обработчика |

Старый общий `models/formulas.csv` и старый loader удалены. Обратная совместимость с ними не поддерживается.

## `kind`

### `direct`

Одна строка модели соответствует конкретному исходному коду.

Пример 802:

```csv
802,41,f802.14,direct,main,14,,total,Всего активов,,I. АКТИВЫ,thousand_rub,
```

### `formula`

Показатель рассчитывается из нескольких исходных кодов. Сейчас этот режим используется существующими аналитическими показателями 101, 102 и 123.

### `passthrough`

Режим зарезервирован для форм, где ЦБ уже поставляет собственную номенклатуру строк внутри архива. Он нужен для последующего полного раскрытия 101 через `NAMES.DBF` и 102 через `SPRAV1.DBF` без ручного дублирования тысяч строк в CSV.

## Загрузчик моделей

`common/models.py` предоставляет:

```python
load_models(models_dir=None)
get_model_for(models_df, form="802")
validate_model(model_df)
```

Загрузчик проверяет:

- точный schema CSV;
- соответствие `formXXX.csv` значению `form`;
- уникальность `id`;
- уникальность `order`;
- допустимые `kind`;
- обязательные поля каждого `kind`;
- допустимые единицы;
- существование `parent_code` внутри dataset.

## Canonical long

Внутренний результат формы имеет стабильный набор смысловых колонок:

```text
Форма
Дата
REGN
Банк
IndicatorId
Код
Показатель
Раздел
Measure
Значение
Единица
```

`IndicatorId` является внутренним ключом показателя. Русское название не используется как идентификатор.

Это принципиально для 802: название `цифровые финансовые активы` встречается в строках `4.3`, `5.4`, `6.6`, `15.7` и `16.7`.

## Wide / Excel

Excel-представление выбирается через поле `excel_profile` в едином реестре форм.
Canonical long при этом не меняется: профиль отвечает только за пользовательское
представление готовых данных.

### `standard`

Стандартный профиль сохраняет прежний одно-листовый формат. Разворот выполняется
по `IndicatorId + Банк`, а не по `Показатель + Банк`.

Если у формы есть официальный код строки, Excel получает структуру:

```text
Код | Показатель | Банк | дата1 | дата2 | ...
```

Для чисто расчетных форм, где `Код` пустой, лишняя пустая колонка автоматически не выводится.

### `hierarchical_statement`

Профиль предназначен для крупных иерархических форм. Сейчас его использует 802.
Он формирует три листа:

```text
Обзор
Полная форма
Данные
```

`Обзор` содержит только строки верхнего уровня модели (`parent_code` пустой) и
сохраняет сравнительный порядок `показатель -> банк`. Для 802 это 34 строки
формы на каждый банк.

`Полная форма` содержит все строки и использует порядок `банк -> order модели`.
Для 802 это 86 строк на каждый банк. Уровень вложенности рассчитывается строго
по `parent_code`, отображается отдельной колонкой и применяется как Excel-indent
к названию показателя. Строки также получают outline-уровни Excel, поэтому
детализацию можно сворачивать и разворачивать штатными средствами книги.

`Данные` сохраняет canonical long и добавляет структурные поля модели:

```text
Порядок
РодительскийКод
Уровень
```

Такой лист предназначен для Power Query, сводных таблиц, формул и дальнейшей
машинной обработки. Физические корректировки 802 в стандартную книгу не
размножаются: пользовательская витрина по-прежнему использует `measure=total`.

## Форма 0409802

Официальный архив строится как:

```text
https://www.cbr.ru/vfs/credit/forms/802-YYYYMMDD.rar
```

Основной DBF:

```text
PK802ГГММ.dbf
```

Физическая схема 802 менялась во времени. Для стандартной витрины обязательны:

```text
REGN_GKO
STR
VSEGO
```

Поля корректировок читаются как дополнительные физические каналы, если они
есть в конкретной версии DBF:

```text
KORR_P
KORR_M
KORR_GR
```

В частности, исторические DBF содержат `KORR_P` и `KORR_M`, но не содержат
`KORR_GR`; в актуальной схеме с 01.04.2026 поле `KORR_GR` уже присутствует.
В `form802.py` доступные поля преобразуются в normalized raw:

```text
REGN
CODE
consolidation_plus
consolidation_minus
intragroup_adjustment
total
```

`STR` всегда остается строкой. Коды `2.1.1`, `11.1.2`, `31.3` не преобразуются в числа.

### Полный каталог 802

`models/form802.csv` содержит все 86 строк текущего публичного основного баланса от строки `1` до строки `34` с подстроками и иерархией `parent_code`.

Ключевые контрольные строки:

```text
1
14
15.4
15.5
21
32.1
34
```

Все строки имеют:

```text
kind=direct
dataset=main
measure=total
unit=thousand_rub
id=f802.<STR>
```

Разделы:

```text
I. АКТИВЫ
II. ПАССИВЫ
III. КАПИТАЛ
```

Справочные подразделы после основного баланса в модель искусственно не добавляются: они должны подключаться только после подтверждения отдельного публичного набора DBF.

### Корректировки 802

Семантический каталог описывает экономическую строку один раз. Он не размножает каждую строку на четыре показателя.

Стандартная пользовательская витрина использует:

```text
measure=total -> VSEGO
```

При этом physical normalized raw имеет стабильные колонки:

```text
KORR_P  -> consolidation_plus
KORR_M  -> consolidation_minus
KORR_GR -> intragroup_adjustment
VSEGO   -> total
```

Если какого-либо поля корректировки нет в конкретном историческом DBF, его
каноническая raw-колонка остается пустой. Отсутствие дополнительной корректировки
не блокирует выгрузку `measure=total`.

Получить raw можно напрямую:

```python
import pandas as pd
from stratbox.macrobanks.cbr_forms.forms import form802

raw = form802.run_raw(
    dates=[pd.Timestamp("2026-04-01")],
)
```

### Пустота и ноль

Для direct-форм действует жесткое правило:

```text
blank != 0
```

Если ЦБ не раскрыл значение, в long остается пустое значение. Если в DBF передан настоящий `0`, в long остается ноль.

## 135 и 805

135 и 805 переведены со старой конструкции `metric_form + expression "FIELD == code -> VALUE"` на общий `DirectDatasetSpec`.

Текущий охват данных пока не расширялся:

- 135 — фактические значения нормативов из раздела 3;
- 805 — текущий набор нормативов банковской группы.

Теперь они используют тот же разделенный контракт:

```text
physical field mapping in Python
+
semantic direct rows in formXXX.csv
```

Это создает нормальный путь для дальнейшего добавления `control_value`, `note`, нескольких dataset 805 и других каналов без очередного отдельного движка.

## 101, 102 и 123

Их существующая расчетная логика сохранена, но модели перенесены в отдельные CSV и каждый выходной показатель получил стабильный `IndicatorId`.

Следующий логичный этап полноты форм:

- 101 — добавить `passthrough` полного B1 и номенклатуру из `NAMES.DBF`;
- 102 — добавить `passthrough` и названия из `SPRAV1.DBF`;
- 123 — добавить полный официальный каталог строк;
- 135 — добавить `actual`, `control_value`, `note` и отдельный dataset операционных дней;
- 805 — добавить остальные опубликованные разделы как отдельные dataset.

Это развитие не требует изменения текущего CSV-schema.

## Реестр форм

Единый реестр расположен в:

```text
forms/registry.py
```

`forms="all"` включает `802`. Реестр также хранит собственную отчетную
периодичность формы. Для 802 зафиксирована квартальная сетка с датой на начало
квартала (`Q/start`), поэтому месячный Run All автоматически обращается к 802
только на `01.01`, `01.04`, `01.07`, `01.10`. Общая месячная сетка остальных
форм от этого не меняется.

## Проверки

Тесты `tests/unit/macrobanks/cbr_forms/` проверяют:

- schema всех model CSV;
- соответствие имени файла коду формы;
- уникальность `id` и `order`;
- контракты `direct/formula/passthrough`;
- объединение всех моделей;
- 86 строк 802;
- уникальность кодов 802;
- наличие контрольных строк;
- отсутствие коллизии повторяющихся названий;
- сохранение `blank != 0`;
- разделение одинаковых названий в wide через `IndicatorId`;
- три Excel-листа 802 и их ожидаемое число строк;
- порядок `банк -> строка формы` на полной витрине;
- уровни иерархии из `parent_code`;
- квартальную reporting cadence 802 внутри месячного Run All;
- fail-fast при дублированных физических ключах `(REGN, CODE)`;
- обработку `pd.NA`/`NaN` как пустого значения кода.

Для полного интеграционного теста с Банком России в среде должны быть доступны:

- `dbfread`;
- `unrar`, `7z` или `7zz`;
- сетевой доступ к `www.cbr.ru` либо настроенный корпоративный сетевой слой Stratbox.
