# 02-base-study

## Role

Основная свежая Research-ветка первой эпохи. Здесь формируется базовая картина фактического текущего состояния Strategy Box как проекта.

Research этой ветки может охватывать несколько implementation owners Strategy Box в одном месте, если вопрос относится к общей архитектурной программе. Отдельные дублирующие каталоги по репозиториям для этого не создаются.

## Research baseline

Для каждого исследуемого компонента первичный baseline — его собственный текущий repository owner: код, упаковка, документация, тесты и инженерные проверки.

Текущий состав включает:

- `stratbox` — core;
- `stratbox-windows` — Windows application/surface.

`../01-old-notes/` используется как дополнительный исторический источник вопросов, гипотез и возможных пропусков. Он не заменяет проверку по текущему состоянию.

AppDock является отдельным внешним проектом. Его материалы используются только тогда, когда нужно проверить Strategy Box-side integration boundary.

## Scope

Исследование может охватывать:

- фактическую архитектуру и границы core/application;
- доменную бизнес-логику и нейтральную инфраструктуру;
- application orchestration и surface semantics;
- общие operation/scenario/result/artifact contracts;
- внешние и внутренние интерфейсы;
- данные, реестры и ресурсные зависимости;
- переносимые части будущих platform surfaces;
- тестовое и документальное покрытие;
- межрепозиторный version/contract drift;
- технический долг, противоречия и слабые места;
- варианты целевой переработки и дальнейшего развития.

Research Result остаётся исследовательским выводом до отдельного решения о его переносе в текущий Product, Knowledge, документацию или код.

Новые подкаталоги внутри ветки создавай только при реальной отдельной ответственности или устойчивом наборе артефактов.
