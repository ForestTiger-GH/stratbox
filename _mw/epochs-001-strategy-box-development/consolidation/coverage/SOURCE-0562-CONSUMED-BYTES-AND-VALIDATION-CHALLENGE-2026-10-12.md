## 2. Concrete candidate-design defects found by applying the source tests

The tenth-packet set's `docs/lcd/data/used-input-receipt-construction.md` originally showed `OriginalByteIdentity` as acquisition evidence, but accepted an externally constructed `CapturedPayload` into `decode_with_used_receipt` without recomputing the digest. A frozen dataclass holding `content: bytes` does **not** ensure that `acquisition.actual_bytes.sha256` covers those bytes. Worse, a mutable transport buffer could be hashed then changed before parsing by a retained provider reference. Neither issue is proof of a bug in **current core implementation**, because this code exists only in the LCD document.

- **D-0562-01 — actual bytes vs claimed bytes:** the candidate now seals a mutable `bytearray/memoryview` into immutable `bytes` before capture and verifies byte count and SHA at consumption; mismatches raise typed `InputEvidenceMismatch` **before invoking the domain decoder**. A large-source streaming version should use one controlled hash/read pipeline rather than copy all bytes merely to meet this model. This addresses original T01/T07 and the source §14.1 race.
- **D-0562-02 — false format validation:** the earlier candidate wrote `format_validation=FORMAT_VALID` after a generic `ByteDecoder.parse()` returned anything, even if that parser never produced a format-qualified witness. The revised `DecodedPayload` carries a distinct format verdict and evidence reference; unless it is `FORMAT_VALID`, the bridge stops before `DomainInputValidator.qualify()`. This sharpens T05 and preserves that actual workbook structure does not validate economic semantics. **The decoder remains a trusted and separately conformance-tested component**; a self-asserted verdict from arbitrary plugin code cannot certify true format validity.
- **D-0562-03 — naive timestamps:** a method named `now_utc` could still return a naive or non-UTC-offset datetime. The candidate now refuses it with `CaptureClockInvalid` instead of issuing a mislabeled UTC acquisition receipt. This supports original T16. The check concerns *representation*, not measured clock drift, official publisher issuance time or trusted-time certification.
