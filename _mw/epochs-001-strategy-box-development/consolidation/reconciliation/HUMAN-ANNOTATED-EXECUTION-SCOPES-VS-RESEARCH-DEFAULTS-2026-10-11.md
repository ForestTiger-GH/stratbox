## 2. Three material collisions to preserve, not silently resolve

### A. Known-team shared chats versus Internet-facing Web

The local team concept expects shared conversation visibility and lightweight participant identity. A separately envisioned publicly reachable web interface needs real authentication/session boundaries even if the initial operator prefers minimal setup cost. Applying a mere nickname to an Internet-facing mutation API would be an unsafe extrapolation of local trust. The product must define at least two explicit deployment profiles: closed trusted team versus authenticated Internet/shared service, with different identity, ACL, visibility and log redaction assumptions. This is a **research-qualified security boundary**, not a choice of particular login framework or a claim that Web already works.

### B. Local close ends work versus detached host Jobs

The source's default local-interruption mental model should not be overwritten by a future always-on host scheduler. It is feasible to expose both modes if each clearly states actual execution owner and stop semantics:
- `LOCAL_FOREGROUND`: close/cancel requests stop and the app reports actual effect/recovery state;
- `HOST_ADMITTED`: acknowledged hosted Jobs can outlive the client's browser/window session if a real durable host is deployed and authority remains there.
The interface must never promise survival of a local process it cannot guarantee, nor silently cancel a host Job by closing a client window. Choosing the second mode is not automatic.

### C. Cheap provenance versus full Knowledge graph

An observed-at receipt for actual downloaded inputs plus version/digest **when material and available** can be useful without introducing a global watched registry of every bank or macroeconomic indicator. A domain-specific heavy solver may justify richer evidence. Users should not be required to enter exhaustive manual methodologies into every Excel report simply because a research ontology contains a `MethodDefinition` object. Conversely, a simple timestamp is insufficient proof of byte identity or historical reproducibility; the interface must be honest about that proof ceiling.
