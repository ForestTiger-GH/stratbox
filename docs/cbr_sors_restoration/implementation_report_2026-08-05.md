# CBR SORS Restoration — отчёт о полном внедрении

Дата: 2026-08-05  
Версия Strategy Box: `0.4.0`

## Что внедрено

Домен `stratbox.macrobanks.cbr_sors_restoration` полностью перестроен без слоя обратной совместимости.

Основные изменения:

1. Excel-адаптеры разделены по источникам и формируют единый source GRID с устойчивыми `observation_id`, SHA-256, координатами исходной ячейки и half-open публикационными интервалами.
2. `01_05_D` добавлен как опциональный источник проверки и истории. Он не участвует в strict bounds и не может молча сузить четырёхкнижную strict-модель.
3. Созданы отдельные реестры 96 опубликованных географических узлов, 85 атомарных территорий, 88 классов ОКВЭД2 и публикационных категорий `PUBLISHED_OTHER`.
4. Введён quantity/relation graph: 29 920 компонентных количеств, 44 880 пользовательских метрик и агрегатные публикационные количества.
5. Реализовано двунаправленное deterministic interval closure с сохранением открытых границ, fixed point и полным derivation ledger.
6. Publication-zero `[0; 0,5)` исключается из очереди LP-сертификации, но не превращается в математический ноль и остаётся в Solver-модели как допустимая микромасса.
7. Strict LP компилируется только из атомарных компонент; дубли публикационных выражений объединяются, exact-fixed переменные подставляются, finite closure bounds передаются в колонки.
8. Открытые границы переводятся в ближайшие допустимые floating-point Solver bounds через `numpy.nextafter`, без произвольного epsilon.
9. Реализованы отдельные official-`highspy` feasibility, batch min/max, reset модели, retry, per-solve и batch time limits, partial results и `solver_runs_grid`.
10. Реализован двухэтапный elastic conflict solver для настоящего `INFEASIBLE`.
11. Основной результат всегда содержит полный `regional_okved2_grid` из 44 880 строк, включая unresolved-клетки.
12. Closure-идентификации видимы как `identified_value` и `PROVISIONAL_*`, но становятся `value` и strict facts только после подтверждённой общей feasibility.
13. Реализован Pivot по региону и по классу ОКВЭД2.
14. Excel-export переведён на нормализованную книгу: компактный полный GRID и отдельные листы `Regions`, `OKVED2`, `Metrics`, а также Pivot и диагностика.
15. Conditional bridge вынесен в отдельный поддомен, выключен по умолчанию, получает strict bounds и никогда не блокирует strict-result.
16. Добавлены unit-, real integration- и opt-in performance gates для structural pass, 100/1 000 LP-целей, bridge optimum и полного Excel.
17. Старые плоские модули и дублирующая документация удалены.

## Ограничение проверочной среды

В sandbox отсутствует официальный `highspy`, совместимый с текущим Python 3.13. Поэтому новая official-HiGHS feasibility и target min/max в этой среде не были выданы за подтверждённый Solver-pass.

Поведение при отсутствии зависимости проверено:

- source preparation и closure завершаются;
- полный GRID и Pivot доступны;
- 11 274 идентификации имеют статус `PROVISIONAL_*`;
- `strict_facts_grid` остаётся пустым до feasibility;
- статус равен `SOLVER_UNAVAILABLE`, а не `INFEASIBLE`;
- bridge также возвращает частичный структурированный результат и не портит strict-result.

Для канонического Solver-прогона требуется установка:

```text
pip install "stratbox[sors-restoration]"
```

или официальный `highspy>=1.11,<2`.
