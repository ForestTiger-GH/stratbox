# Внедрение и корректирующая проверка RKVS Target Engine

Дата: 2026-08-06  
Версия Strategy Box: `0.6.1`  
Версия правил: `sors-rkvs-2026.5`

## Цель

Перестроить SORS restoration вокруг отдельной базовой РКВС:

```text
регион × класс ОКВЭД2 × денежный компонент
```

Для каждой цели система пошагово добавляет связанные официальные уравнения и принимает только единственное допустимое значение.

## Основная реализация

1. Каталог всех 29 920 базовых компонентных целей.
2. Постоянный quantity/relation graph и одна глобальная sparse LP.
3. Persistent affected closure без полной пересборки графа.
4. Cumulative local horizons от CELL до GLOBAL_CONNECTED.
5. Безопасная outer-approximation проекция глобальной модели.
6. Внутренняя служебная проверка единственности одной координаты.
7. Разделение exact и publication-bucket uniqueness.
8. Append-only Fact Ledger с supersession и proof trail.
9. Каскад direct fact → affected closure → соседние факты.
10. Приоритетная очередь и fixed-point orchestration.
11. Feasibility gate: без подтверждённой глобальной совместимости факты не принимаются.
12. Crosswalk остаётся отдельным evidence layer до исправления несовместимых mapping-профилей.

## Корректировки 0.6.1

### Открытые публикационные границы

Initial LP ранее вычисляла Solver-safe endpoints, но передавала в column bounds исходные semantic endpoints. На реальном срезе произвольное решение коснулось 135 запрещённых открытых верхних границ.

Исправлено:

- initial compiler использует Solver-safe column bounds;
- обновление bounds после каскада использует ту же функцию;
- publication rows и Crosswalk rows обрабатываются единообразно;
- не достигнутый endpoint сдвигается внутрь интервала на `point_tolerance`, поскольку одного `nextafter` меньше обычной LP feasibility tolerance.

### Endpoint-логика deterministic closure

Исправлено наследование строгости при остаточной нижней границе. Если алгебраический остаток отрицателен, активная граница задаётся независимой неотрицательностью `x ≥ 0`, поэтому ноль достигнут. Только строгое равенство остатка нулю способно исключить `x = 0`.

После свежего расчёта на 01.06.2026:

- 29 918 из 29 920 компонентов допускают точный ноль по нижней границе;
- две московские РКВС имеют действительно строгую положительную нижнюю границу;
- прежние 11 274 publication-zero facts сохраняются.

### Производительность глобального доказательства

- `GLOBAL_CONNECTED` использует persistent Solver session;
- между целями обновляются column bounds без повторной загрузки sparse-матрицы;
- локальные и глобальные горизонты имеют разные Solver strategies;
- по умолчанию локальные задачи используют simplex, глобальная — IPM;
- повторяется только незавершённое направление `MIN` или `MAX`;
- Solver audit фиксирует алгоритм, reuse сессии и reuse basis/state.

## Доказательный инвариант

Каждая локальная система создаётся удалением строк из глобальной модели при сохранении всех переменных выбранных строк. Следовательно, глобальное допустимое множество является подмножеством локального. Единственность цели в локальной модели является достаточным доказательством её глобальной единственности.

## Проверка на реальных данных 01.06.2026

Использованы пять книг рабочего набора пользователя, включая дополнительную региональную таблицу для межтабличной проверки.

Фактический путь:

```text
16 450 source observations
→ 85 atomic regions
→ 88 OKVED2 classes/categories
→ 76 118 quantity nodes
→ 46 198 sum relations
→ 7 initial closure passes
→ 29 920 active RKVS component variables
→ 1 318 official sparse constraints
→ 409 200 non-zero matrix coefficients
```

Свежая модель с исправленными closure endpoints и robust open bounds:

- глобальная feasibility: `OPTIMAL`;
- попаданий на семантически открытые endpoints: 0;
- 11 274 component facts на точности публикации;
- ненулевых доказанных точек в проверенном STRICT-наборе пока нет.

Реальный пример ненулевого сужения:

```text
г. Москва × класс 64 × overdue_fx
closure lower bound: 44 950.5
GLOBAL lower bound: 45 219.0 млн руб.
```

Полная глобальная максимизация отдельных координат остаётся наиболее тяжёлой частью из-за высокой вырожденности системы. Исправления не заменяют её эвристикой и не повышают незавершённый proof до факта.
