# Методология восстановления SORS

## 1. Искомый объект

Искомый куб:

```text
атомарный регион × класс ОКВЭД2 × денежный компонент
```

Компоненты непересекающиеся:

- `performing_rub`;
- `overdue_rub`;
- `performing_fx`;
- `overdue_fx`.

Шесть пользовательских метрик являются суммами этих компонентов.

## 2. Публикационное округление

Опубликованное значение `v` млн руб. задаёт интервал истинной величины, совместимый с округлением. Опубликованный ноль является `ZERO_AT_PUBLISHED_PRECISION`, пока система не докажет математический ноль.

## 3. STRICT

STRICT формирует допустимое множество из официальных маржинальных сумм, неотрицательности и географической атомизации. Нулевая ошибка feasibility означает совместимость ограничений, но не уникальность внутренних клеток.

## 4. CROSSWALK как система уравнений

Старая классификация сначала раскладывается на непересекающиеся атомы. Для допустимого перехода вводится неотрицательный поток:

```text
z[region, legacy_atom, okved2_class, component]
```

Сумма исходящих потоков атома воспроизводит его старую публикацию. Сумма входящих потоков класса воспроизводит новую публикацию. Одна переменная одновременно участвует в обеих сторонах, поэтому денежная масса сохраняется автоматически.

Пример:

```text
agriculture_hunting_services → 01
forestry → 02
```

Вместе со старой иерархией это эквивалентно уравнениям:

```text
old_narrow_agriculture = class_01
old_broad_agriculture_forestry = class_01 + class_02
```

Условность относится к принятому mapping-сценарию. Внутри сценария ограничения являются жёсткими.

## 5. Min/max-сертификация

Для каждой цели решаются две LP при том же наборе ограничений. Значение принимается только при точечной или публикационной идентификации. Широкий диапазон остаётся диапазоном; midpoint и произвольное решение Solver не используются.

## 6. Сценарная устойчивость

Для нескольких допустимых mapping-сценариев формируется envelope:

```text
robust_lower = min(lower_scenario)
robust_upper = max(upper_scenario)
```

Только схлопнувшийся envelope даёт `CROSSWALK_SCENARIO_ROBUST_*`.

## 7. Техническая категория

`completion_of_settlements` представлена явными потоками с признаком `TECHNICAL_UNALLOCATED`. Она расширяет неопределённость честно и видимо. Она не является бесплатным optimizer residual и не создаёт восстановленное значение без min/max-сертификации.
