# Методология целевого восстановления РКВС

## 1. Базовая неизвестная

Для региона `r` и класса `c` вводятся четыре неотрицательные величины:

```text
x[r,c,performing_rub]
x[r,c,overdue_rub]
x[r,c,performing_fx]
x[r,c,overdue_fx]
```

Производные метрики являются точными суммами компонент. Такое представление автоматически обеспечивает `overdue <= debt`.

## 2. Источники уравнений

STRICT использует:

- региональные итоги по RUB/FX и просрочке;
- национальные итоги классов ОКВЭД2;
- федеральные округа × разделы ОКВЭД2;
- российские итоги;
- географическую атомизацию;
- неотрицательность;
- интервалы публикационного округления.

## 3. Пошаговая локальная дедукция

Для одной РКВС сначала используются её текущие bounds. Затем добавляются региональные, окружные и национальные уравнения. После каждого расширения выполняется проверка: может ли целевая координата принять другое опубликованное значение.

Ранний локальный горизонт содержит меньше ограничений и потому допускает не меньше решений, чем полная модель. Это делает раннее доказательство единственности сильнее, а не слабее.

## 4. Внутренняя проверка единственности

Для целевой координаты `x_i` решаются две служебные задачи:

```text
min x_i
max x_i
```

Они не формируют пользовательский bounds-result. Их единственная роль — доказать отсутствие альтернативы.

РКВС принимается, если:

- обе задачи завершены оптимально;
- система глобально совместима;
- экстремумы совпадают с tolerance; либо
- оба экстремума находятся в одном публикационном bucket.

Одна произвольно найденная Solver-таблица доказательством не является.

## 5. Детерминированный каскад

Для отношения `parent = Σ children` closure выполняет:

- children → parent;
- parent и остальные children → отдельный child.

После фиксации РКВС новые остатки могут определить соседние РКВС. Fixed-point цикл продолжает работу до отсутствия новых bounds и фактов.

## 6. Публикационная точность

Опубликованный ноль означает интервал, округляющийся в ноль, а не абсолютный ноль рублей. Поэтому Fact Ledger различает:

- `EXACT`;
- `PUBLISHED`;
- exact zero;
- zero at published precision.

Publication-bucket не схлопывается искусственно в математическую точку: в quantity state сохраняются доказанные нижняя и верхняя границы, а в пользовательском значении хранится опубликованный миллион.

## 7. Feasibility gate

До продвижения фактов вся глобальная STRICT-система должна пройти feasibility. При `SOLVER_UNAVAILABLE`, `TIME_LIMIT` или ином незавершённом статусе closure-bounds остаются диагностическими, но принятый Fact Ledger пуст.

## 8. Crosswalk

Crosswalk может добавлять новые уравнения лишь как отдельный доказательный профиль после глобальной проверки совместимости. Мягкие отношения, optimizer priors и benchmark-значения в STRICT Fact Ledger не допускаются.
