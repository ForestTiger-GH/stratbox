# Ошибка наблюдения, неизвестный эффект и сохранность состояния

**Предмет:** отличия отсутствия данных, отсутствия наблюдения, отказа чтения, неопределённого внешнего эффекта и подтверждённого исхода. **Статус:** ограниченное научное объяснение с точной прямой иллюстрацией из Strategy Box; это не спецификация будущего JobManager.

## Семантические состояния

Пустая выборка означает, что проверенная операция успешно просмотрела заданное пространство и нашла ноль элементов. Отказ хранилища означает, что операция **не получила достоверного ответа** о содержимом. Эти наблюдения логически несовместимы как равные значения ответа: `EMPTY_SUCCESS` и `READ_FAILED` требуют разных оснований и разной эксплуатационной реакции.

`HistoryPersistenceService._load_list()` в текущем Windows application при ошибке чтения/декодирования JSON и при payload другого типа возвращает `[]`, а `load_into()` заменяет пять коллекций полученными значениями. [Прямой код](https://github.com/ForestTiger-GH/stratbox-windows/blob/959e9c4ce1441124af5111c1e025041714e04d3b/src/stratbox_windows/application/history/persistence.py). Поэтому повреждённый JSON-файл и достоверно пустая история могут стать одинаковой in-memory проекцией. **Это непосредственно подтверждённая статическая потеря различимости**, но отсутствие атомарности или блокировки само по себе ещё не доказывает произошедшую потерю пользовательских данных в реальном deployment.

## Внешний эффект и локальный ответ

Если операция может совершить внешний эффект до того, как вызывающий получит ответ, прерванное соединение создаёт несколько совместимых с наблюдением миров:

| Реальный мир | Что увидел вызывающий | Почему повтор неоднозначен |
| --- | --- | --- |
| Эффект ещё не совершен | timeout | повтор может быть нужен для достижения результата |
| Эффект совершён, ответ потерян | timeout | повтор может воспроизвести эффект второй раз |
| Эффект частично совершён | timeout | автоматический полный повтор может ухудшить состояние |

Таблица — **логический вывод при явно названной асинхронной предпосылке**, а не эмпирический отчёт о конкретном поставщике. Следовательно, `timeout` не доказывает ни `effect_failed`, ни `effect_succeeded`. Идемпотентная identity, удалённая дедупликация, effect receipt и процесс проверки результата относятся к разным механизмам и имеют свои ограничения.

## Две инженерные альтернативы

**Fail closed при повреждении состояния** сохраняет различимость ошибок и блокирует рисковые действия до восстановления, но может прервать простой read-only просмотр. **Degraded read-only** оставляет диагностику доступной, если повреждение явно видно пользователю и новые записи в этот же повреждённый authoritative scope запрещены. Допустимость варианта зависит от роли истории: необязательная recent projection и единственная durable истина имеют разные требования восстановления.

Для аналитических данных аналогична ошибка, когда `UNKNOWN` превращается в zero, а для UI — когда отсутствующий event отображается как подтверждённое завершение. Материальность зависит от полномочий, последствий, обещаний сохранности и наличия независимого source of truth.

## Что известно, а что открыто

**Current evidence:** конкретная Windows JSON-проекция скрывает ряд ошибок в пустой список; domain HTTP downloader возвращает `DownloadResult(ok=False, error)` при неуспехе попыток, сохраняя отличимость такого отказа от успешной пустой загрузки при установленном минимальном пороге. [Download code](https://github.com/ForestTiger-GH/stratbox/blob/8459dc58922b7e8df853cf1d9e8131fa9e132580/src/stratbox/base/net/http.py).

**Не подтверждено:** фактические сбои данной поставки в эксплуатации, платформенное восстановление, глобальная event authority, retry по реальным внешним эффектам, готовая схема полномочий, фактический end-to-end recovery. Наличие static control flow не заменяет fault-injection и проверку deployed configuration.

**Reopen:** изменение persistence/error contracts, появление transactional state owner, новые подтверждённые incident datasets, определение risk/persistence guarantee компетентным владельцем.

**Продуктовые последствия — отдельно:** возможные запреты на silent fallback, требования к effect receipts и recovery нужны для обсуждения Target WHAT/HOW. Содержание этой статьи само по себе **не принимает** их как продуктовые обязательства.
