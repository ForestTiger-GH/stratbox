# SORS Restoration V2 — метод и доказательные статусы

## Целевой объект

Для одной отчётной даты строится куб:

```text
атомарный регион × класс ОКВЭД2 × денежный компонент
```

Четыре непересекающихся компонента:

```text
performing_rub
overdue_rub
performing_fx
overdue_fx
```

Из них формируются шесть пользовательских метрик: `debt_rub`, `debt_fx`, `debt_total`, `overdue_rub`, `overdue_fx`, `overdue_total`.

## Источники

- `01_05_A`: 96 географических узлов × 26 традиционных строк × 6 метрик;
- `01_02_A`: РФ × 26 традиционных строк × 6 метрик;
- `01_02_C`: РФ × 80 явно опубликованных классов + `Прочее` × 6 метрик;
- `01_03_C`: 8 федеральных округов × 16 разделов/групп × 2 метрики.

Все опубликованные значения задаются интервалами округления, а не машинными равенствами.

## Жёсткая модель

Жёсткий слой использует:

1. все региональные строки `ВСЕГО`, включая агрегированные географические узлы;
2. национальную традиционную строку `ВСЕГО`;
3. все национальные публикации классов ОКВЭД2;
4. все публикации разделов ОКВЭД2 по федеральным округам;
5. неотрицательность.

Категория `Прочее` представлена суммой восьми реальных классов ОКВЭД2, которые не публикуются отдельно.

Для каждой цели вычисляются:

```text
strict_lower = min(target)
strict_upper = max(target)
```

Если диапазон схлопнулся или полностью попал в один публикационный bucket, значение получает `STRICT_*`.

## Методологический bridge

Региональные традиционные отрасли содержат ценную информацию, но не образуют официальную денежную матрицу перехода в ОКВЭД2. Поэтому V2 использует отдельный версионированный bridge со статусом `METHODOLOGY_DERIVED`.

Для каждой традиционной строки задаётся родственая группа классов ОКВЭД2. Оптимизатор минимизирует взвешенное абсолютное отклонение от всех 13 968 традиционных отраслевых наблюдений при безусловном соблюдении жёстких публикационных ограничений.

Bridge никогда не создаёт `STRICT`-факт.

### Singleton profile

Если традиционная строка связана с одним классом ОКВЭД2, fitted-значение этой строки напрямую задаёт условное значение класса для данного региона и метрики. После проверки публикационного bucket присваивается:

```text
BRIDGE_SINGLETON_PROFILE_AT_PUBLISHED_PRECISION
```

### Local profile

Для многоклассового перехода фиксируются fitted-маржи только целевого региона. Остальные регионы остаются свободными под национальными и окружными ограничениями. Затем выполняется min/max цели.

Если диапазон схлопнулся, присваивается `BRIDGE_LOCAL_PROFILE_*`.

## Почему два слоя не смешиваются

- `STRICT` показывает то, что вынуждено официальными публикациями.
- `BRIDGE_*` показывает то, что вынуждено выбранным минимально-ошибочным методологическим мостом.

Обе записи могут находиться в `facts_grid`, но имеют разные `evidence_layer`, `status`, диапазон и версию mapping.

## Одна итерация

V2 намеренно выполняет одну полную итерацию:

```text
parse
→ canonical GRID
→ validation
→ hard publication model
→ bridge optimum
→ strict min/max
→ bridge profile certification
→ FACTS + BOUNDS + AUDIT
```

Циклическое pruning/остаточное замыкание оставлено для следующей волны. Оно сможет ускорить расчёт и открыть дополнительные остаточные значения, но не должно менять доказательную семантику V2.
