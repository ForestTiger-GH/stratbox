## Consequences for admitted Strategy Box host variants

**Windows/AppDock host:** this pinned AppDock can dispatch an ordinary local background/detached process. A `dedicated_server`-typed process might launch a future Strategy Box host, **conditionally**. The host still must provide the actual app-level listener/connection, authorization, Case/Job/Artifact semantics and service readiness. Selecting `host_delegated` on the pinned execution path would explicitly fail. A separate Windows client must attach through a real supported interface; one-versus-two repositories is open.

**Web/domain host:** AppDock opening a browser URL creates no Web-host backend. A real host must run separately, expose a secured site/domain and serve authorized clients. Browser bridge success differs from domain host readiness and analytic execution.

**Strict evidence levels:** (1) schema-declarable, (2) locally process-launchable on this pinned AppDock code, (3) installed host service actually ready, (4) two-client authorized and recovered app operations. Only (1) and bounded (2) have direct code evidence here. AppDock launch state does not own Strategy Box's domain data or verified effects.

**Reopen:** installed AppDock revision, actual implementation of delegated/remote attach, concrete host process/test, or Product Decision. No current Strategy Box release claim is made.

**Observed compatibility limit:** the pinned Windows manifest declares local foreground desktop activation; its entry adapter refuses wrong World/Surface IDs, missing core/desktop runtime bindings and different binding environments. Its strict local Context parser is separate from AppDock's public decoder. Neither isolated parser nor local manifest implies a Web/Android host-client release. This directly constrains future `stratbox-application` acceptance and [activation LDD vectors](../ldd/integration/activation-contract-verification.md).

**Open verification:** execute real schema/manifest admission on a pinned platform installation, attest bound bytes via the actual platform authority, test duplicate bindings and tampered Context under the admitted trust model, and run genuine Windows host/client authentication and failure tests. No Product Decision, host implementation or current availability claim follows from these static observations.
