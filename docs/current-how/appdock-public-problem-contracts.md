## Consequential observed boundary

- **Success:** `Recorder.record` returns a real `ProblemOccurrence`; callers may derive its real `ProblemRef` according to the public contract. The platform owns this occurrence; a Strategy Box Case may retain a permitted reference without copying the canonical record.
- **Confirmed `NOT_WRITTEN` failure:** `RegistrationFailure.state` represents no confirmed persisted registration. The calling application's domain outcome remains an independent fact.
- **`OUTCOME_UNKNOWN` failure:** the recorder could have committed despite missing response. If `candidate_ref` accompanies the failure, it **must not be treated as a confirmed registered reference**. Query it only when the exact installed platform owner permits an authenticated lookup, then respect all five query outcomes.
- **Dual failure and authorization:** a domain failure and its recorder failure are two causally connected observations. No raw exception or traceback becomes user-visible by default, and a successful local platform query does not grant access to the other user's Case or diagnostic evidence.
- **Current Strategy Box integration:** the pinned Windows surface declares only local foreground activation, and the pinned AppDock [launcher](appdock-activation-host-attachment-boundary.md) reports `BACKEND_UNAVAILABLE` for the inspected `host_delegated` route. Neither code path verifies an installed cross-app Recorder bridge.

**Evidence limit and next proof:** select an actual published AppDock interface supported for external clients, build one neutral Strategy Box adapter under the correct implementation owner, verify registration/read/error and ACL across two installed host/client surfaces, then inject lost acknowledgement and journal corruption. Until then these source types are concrete **AppDock contracts**, while actual Strategy Box host integration, durable end-to-end logs and recorder authorization remain **unproven**.

**Truth separation:** a platform `ProblemRef` is an owner-confirmed reference, not proof of Strategy Box Run effect or identity/ACL for a new client. An `OUTCOME_UNKNOWN` recorder failure, optional candidate reference or cancelled operation cannot fabricate a confirmed Session `ProblemRef`. Diagnostic `FAIL` plus `PARTIAL` coverage is coherent; neither means that a complete host health probe was performed. Session, Task and Shell mappings are reported at this pinned AppDock owner revision, while authenticated external Strategy Box participation, service readiness, durable audit, evidence export and Web/Android integration remain unproven.

The [candidate host problem LDD](../ldd/observability/host-problem-receipts-and-evidence-degradation.md) retains a conditional integration contract. Actual installer revision, permission boundary, native 5E certification and installed fault probes require separate evidence and Product decisions.

## External Observability architecture README: implemented slice versus deferred contours

At the same exact public AppDock revision, the complete 235-line [Observability architecture README](https://github.com/ForestTiger-GH/AppDock/blob/a4d87c643e620e54e04083d4d0b8d867513e7065/docs/architecture/observability/README.md) (blob `6c7cb89940907f4b4b65e86981b25dd503ccbe02`) confirms the authority hierarchy: target meaning belongs to the target model; implementation sequence and gates to the execution plan; **current allowed scope and certification status to the leading Current authoritative state of implementation status**. Numerous older milestone paragraphs in the README are explicitly historical, even where their present-tense wording differs from its opening 5E handoff.

The reported **pre-Node Shell startup** path deliberately publishes only a bounded safe `ShellStartupFailure`; an exception before a Node recorder exists produces **no fabricated ProblemRef or EvidenceRef**. The reported worker path logs technical exception detail locally while passing only the restricted `TaskFailure` shape through Shell/Studio; generic task transport does not carry live exception or unrestricted technical details. The existing source-focused 5E pass does **not** establish that every early crash will produce a durable record: the same README explicitly defers the emergency/bootstrap evidence sink and Observability self-health to a **future Milestone 6A, after 5E native certification**.

Other explicitly deferred work includes Build/Source Acquisition external canonical-ref integration, broad semantic Events, Evidence/Audit/Support, Release/Runtime transparency, cross-platform remote diagnostics, incident/fleet, MCP/A2A and platform-specific evidence handling. These are not currently adopted Strategy Box capabilities or released AppDock API promises. A future Strategy Box host must provide its own truthful early-start and post-crash evidence obligations and negotiate only installed, version-confirmed external platform capabilities.

**No change to reliance state:** this additional owner-level document corroborates the [5A–5E status split](#appdock-observability-milestone-authority-versus-strategy-box-adoption-2026-10-12); it does not certify external client registration, actual Windows 5E completion or a runnable host adapter.
