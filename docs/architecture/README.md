# Engineering Product Architecture

**Статус: распределение ответственности ещё не принято как целевой архитектурный baseline.**

Этот раздел будет владеть **распределением реализации**: системным окружением, логическими компонентами, направлением зависимостей, межрепозиторными интерфейсами, профилями размещения и внешними границами.

Он создаёт самостоятельную ценность для согласования аналитического ядра, платформенно-нейтральной прикладной ответственности и отдельных клиентских поверхностей. Детальные механизмы уже описываются в Target HOW: здесь достаточно адресных ссылок, без второй независимой версии одного контракта.

AppDock сохраняет собственную платформенную ответственность; внешняя когнитивная система использует только разрешённые способности Strategy Box. Физическое выделение новых пакетов, сервисов и репозиториев определяется по объективной самостоятельности жизненного цикла, а не по одному названию.
